# 灵犀 · 内心世界

> 私聊专用的连续情绪、待关注事项、每日回顾与身体反应状态插件。

插件会从私聊中提取“可能影响角色内心的事情”和“对后续对话仍有约束或接续价值的事项”，经过确定性规则结算后形成连续心境与待关注目录，并把少量当前状态注入角色的系统提示词。群聊不会分析、落库、结算或注入。

## 快速开始

普通使用不需要编写规则，建议先这样配置：

- **启用插件**：开启。
- **自定义本地规则**：留空，直接使用内置规则。
- **低频消息复核模型链**：可以留空，低频复核会使用当前会话模型；需要快速、低成本处理时可单独选择轻量 Provider。
- **每日深度回顾模型链**：可以留空，每日回顾会使用当前会话模型；需要更稳定的日记和复盘时可单独选择推理能力较强的 Provider。
- **启用低频模型复核**：按需开启。关闭后仍会正常运行本地规则和确定性结算。
- **启用每日结算**：需要每天自动换日、回顾并生成新一天心境时开启。
- **启用模型每日回顾与日记**：需要模型写日记时开启；关闭后每日本地结算仍然执行。
- **启用独立身体反应状态**：需要单独追踪身体敏感和性唤起时开启，不需要时保持关闭。

所有功能只处理私聊。斜杠命令、空消息和群聊消息不会作为普通用户消息分析。AI 最终回复只做不调用模型的待关注事项识别，用于捕获由角色自己提出的明确约定或未来计划；不会作为普通情绪规则或亲密词输入。

## 工作方式

一条私聊消息到来后，处理顺序如下：

1. 内置规则和自定义规则先在本地识别候选证据，不调用模型。
2. 候选证据经过对象、置信度、去重、生命周期和强度约束后，更新心事与当前心境。
3. 本地规则同时保守识别明确约定、稍后计划、明确记忆要求和待接续行动；AI 最终回复中的明确提议先记为待确认事项。
4. 开启独立身体反应状态时，另外检查该条用户消息中的亲密互动词，按人设亲密基线倍率更新身体敏感和性唤起。
5. 开启低频模型复核时，只有本地情绪候选不够确定才会异步调用低频消息复核模型链；当前回复不会等待它。
6. 对话模型请求发出前，插件分别注入少量有效心事、待关注事项和中文身体反应。待关注事项使用独立额度，不占情绪心事数量。

情绪事实会以完整句子保存；账本最多保留 600 字，注入模型时按完整标点收束到 360 字，避免长事件在半句话中间被硬截断。

模型只能提供观察建议。最终状态始终由本地确定性结算器决定，过期或低置信度的模型结果不能直接覆盖当前状态。

## 命令

以下命令仅在私聊中生效。命令前缀按 AstrBot 当前配置使用，通常为 `/`。

| 命令 | 别名 | 说明 |
|---|---|---|
| `/情绪查看` | `/emotion view` | 返回本地渲染的情绪图片，包含情绪数值、身体反应、当前心境、当前有影响的事情和正在关注的事项。 |
| `/情绪状态` | `/心境`、`/emotion state` | 查看当前心境、有效心事、人设亲密基线和身体反应。 |
| `/情绪结算` | `/手动结算`、`/emotion settle` | 立即执行一次本地确定性衰减与心境结算，不调用模型，也不等同于每日回顾。 |
| `/情绪快照重建` | `/重建情绪快照`、`/emotion rebuild` | 清除缓存的“最近实际注入”，并按当前账本重新生成情绪快照文本。不会删除或重算历史状态。 |
| `/情绪日记重跑` | `/日记重跑`、`/emotion diary rerun` | 强制重跑当前逻辑日的每日回顾；启用模型日记时使用模型链，否则生成本地回顾。会替换同一逻辑日原有日记。 |
| `/情绪模型链` | `/心境模型链`、`/emotion providers` | 显示配置的 Provider 回退顺序，以及当前实际可用的 Provider，便于排查模型配置。 |
| `/情绪规则试跑 <文本>` | `/规则试跑 <文本>`、`/emotion rule test <文本>` | 用样例文本测试规则，返回命中项、排除原因和候选证据；不会写入真实状态。 |
| `/情绪注入` | `/心境注入`、`/emotion prompt` | 对比最近一次真实请求中实际装配的情绪块，以及按当前账本实时生成、尚未发送的预览。两者会标明版本差异和北京时间，不会返回人格、日程等其他插件内容。 |

## WebUI 会话载入

WebUI 会从插件已经持久化的私聊账本中列出会话，并自动载入最近更新的一项。右上角的“私聊会话”下拉框用于在多个私聊状态之间切换，不需要手工填写 `unified_msg_origin`。

心事和待关注事项支持长文本自动换行；分类、状态和删除按钮会固定在面板内，在窄屏下也不会被正文挤出边界。

如果页面显示“尚无私聊状态”，表示插件尚未收到可创建账本的普通私聊消息；命令、空消息和群聊不会创建状态。已有账本却无法列出时属于载入异常，而不是聊天轮数不够。

## 与主动对话 Spark 协作

安装并启用 `astrbot_plugin_Spark` 后，插件会通过只读状态接口判断“AI 已成功发送主动消息，但用户尚未回应”。普通长时间没聊天不会产生这类负面状态。

- 默认等待 180 分钟后进入第一阶段，继续等待时按相同间隔有限加深。
- 同一条主动消息的同一阶段只结算一次，插件重启后也不会重复扣减。
- 强度和阶段都有配置上限，避免一次晚回复长期主导整体心境。
- 用户之后发来真实私聊消息时，对应心事会转为缓解；命令、发送失败和手动测试主动消息不会被算作“被忽略”。
- WebUI 的“集成诊断”会显示 Spark 连接状态、当前是否待回应、等待时长和已结算阶段。

相关配置为：**主动消息长期未回应影响情绪**、**主动消息未回应阶段间隔**、**单条主动消息最多结算阶段**和**主动未回应事件最大强度**。

## 配置说明

### 基础与心事

- **情绪查看图片主题**：可选择“自动”“亮色”或“暗色”。自动模式在本地时间 `07:00` 至 `19:00` 使用亮色，其余时间使用低饱和暗色。
- **最多注入的当前事情数量**：正面和负面心事共用数量上限，只影响注入给对话模型的数量，不会删除账本中的其他事情。
- **最多注入的待关注事项数量**：约定、计划、明确记忆要求和待接续内容使用独立数量上限，不与情绪心事竞争。
- **情绪状态注入规则说明**：控制模型提示词开头的状态使用规则。可按需改写；留空使用内置的精简默认说明。
- **内心世界注入位置**：控制整块内心世界内容放在哪里。默认“系统提示词末尾”，最稳定；“临时用户上下文末尾”把整块作为本轮临时内容，离指令更近且不写入聊天历史；“拆分（状态留系统，建议进用户）”把状态快照留在系统提示词，只把回复建议放进临时用户上下文。切换位置后旧位置的内容会自动清理，环境不支持临时上下文时自动回退到系统提示词。
- **心事自然淡化半衰期**：控制未被再次刺激的心事随时间回落速度。数值越大，影响保留越久。
- **低频消息复核模型链**：只用于异步复核本地规则认为不够确定的用户私聊，适合速度快、成本较低的模型。按从上到下顺序失败回退，留空时使用当前会话模型。
- **每日深度回顾模型链**：只用于每日回顾、日记、事件复盘和次日心境建议，适合推理能力较强的模型。按从上到下顺序失败回退，留空时使用当前会话模型。
- **启用低频模型复核**：只对本地规则认为不够确定的消息做异步复核。关闭不影响本地识别、状态结算和提示词注入。
- **自定义本地规则**：可选的额外识别规则。留空时内置规则仍正常工作。

### 每日结算与日记

- **启用每日结算**：开启到点自动换日。插件在设定时间关闭刚结束的逻辑日，完成回顾和确定性结算，并生成新逻辑日的起始心境。
- **每日逻辑日界线**：格式为 `HH:MM`。例如设置 `07:00`，前一天 `07:00` 到当天 `06:59` 算作同一个逻辑日；到当天 `07:00` 后结算这段周期。
- **启用模型每日回顾与日记**：开启时通过每日深度回顾模型链生成第一人称日记、当日摘要、事件观察和次日心境建议。关闭或模型失败时，使用本地结构化回顾，确定性结算仍会执行。
- **日记人格与文风补充**：可选的短文本，只补充已有角色人格的表达方式，例如“句子偏短、偶尔嘴硬”。它不能覆盖第一人称、事实边界、JSON 字段或确定性状态规则；不需要时留空。
- **日记最大字数**：限制模型日记保存长度。
- **每日回顾模型输入字符上限**：限制发送给模型的每日材料长度。
- **未总结尾部消息数**：配合 LivingMemory，限制每日回顾读取的少量近期未总结消息。
- **日记保留天数**：每个私聊会话最多保留多少个逻辑日的日记。
- **每日低权重心境词**：给每日模型回顾的弱参考。它不能编造经历，也不能直接覆盖确定性心境。

每日结算和日记属于同一个“每日回顾入口”，但不是同一个开关：

- 关闭**每日结算**：不会到点自动运行。
- 开启**每日结算**、关闭**模型每日回顾与日记**：仍会到点执行本地结算，并保存本地回顾。
- 两者都开启：到点先回顾刚结束的一天，模型给出日记和心境建议，再由本地结算器生成新一天的权威心境。

模型给出的 `next_mood_proposal` 只占较低权重。未淡去的心事和本地结算结果优先，模型不能直接把心情改成任意状态。

### 人设亲密基线与身体反应

这套状态不等于普通的“喜欢、开心或好感”，也不占心事注入数量。它分成职责不同的两层：

- **人设亲密基线**：全局固定配置，可选择“普通亲密”“很亲密”“非常亲密”或“对你有很强的身体吸引”。它不随聊天和时间变化，只决定相关互动引起身体反应时的敏感程度。
- **身体敏感度**：身体反应被相关互动带动的程度。
- **性唤起**：成人性唤起程度，普通兴奋或开心不会自动算入。

当前身体反应阶段只由身体敏感度和性唤起派生。相关私聊互动只能让这两个数值小幅、有限地变化，需要连续互动才会逐步升档；间隔时间会使身体反应回落。更高的人设亲密档位会放大同一次有效信号，但不会阻止身体反应冷却到平静。连续数值只保存在账本、状态命令和 WebUI 诊断中；对话模型只接收“平静、轻微、明显、强烈”四档中文身体反应，不接收身体敏感、性唤起、当前倾向、能量或紧张的原始小数，避免细微结算导致提示词缓存频繁失效。

**亲密互动规则词检查的是用户发来的私聊消息，不检查 AI 回复。** 用户消息命中一个或多个词时，只会作为一次有上限的身体反应证据，不会直接、无限累积亲密度。旧账本中的意愿、克制和阶段字段继续保留用于兼容读取，但不再参与新的身体阶段计算、提示注入或界面展示。

同一个词可能同时命中普通内置情绪规则，例如“想你”既可能形成亲近倾向的心事证据，也可能在开启独立身体反应状态后影响身体维度；两套状态分别结算。

## 自定义本地规则

### 是否必须写

不必须。内置规则已经覆盖：

- 开心、感谢和被治愈等正向表达；
- 难过、委屈、生气和失望等负向表达；
- 道歉、安慰和关系修复；
- 想念、喜欢、拥抱和亲吻等亲近表达；
- 傲娇、撒娇和熟人玩笑；
- 明显侮辱和真实攻击。

只有角色有专属口头禅、关系称呼或内置词没有覆盖的表达时，才需要添加自定义规则。`custom_rules` 留空不会禁用内置规则。

### 字面匹配示例

下面这条规则会在用户私聊包含“给你带了奶茶”或“记得按时吃饭”时，生成一条偏正面的候选证据：

```json
{
  "id": "daily_care",
  "enabled": true,
  "priority": 20,
  "match_type": "literal",
  "words": ["给你带了奶茶", "记得按时吃饭"],
  "exclude_words": ["他说", "转发", "举例"],
  "action": "create",
  "target": "user",
  "valence": 0.55,
  "intensity": 0.4,
  "confidence": 0.78,
  "meaning": "用户在日常细节中表达了关心"
}
```

### 正则匹配示例

下面这条规则匹配“连续等待/陪伴了若干小时”的表达。JSON 字符串里的反斜杠需要写成 `\\`：

```json
{
  "id": "long_companionship",
  "enabled": true,
  "priority": 30,
  "match_type": "regex",
  "pattern": "陪(了|着).{0,8}(\\d+|一|两|几)个?小时",
  "exclude_words": ["假设", "例如", "台词"],
  "action": "create",
  "target": "user",
  "valence": 0.65,
  "intensity": 0.55,
  "confidence": 0.82,
  "meaning": "用户投入了较长时间陪伴"
}
```

建议先运行 `/情绪规则试跑 <样例文本>`，确认命中与排除结果后再用于真实聊天。非法正则只会禁用对应规则并报告错误，不会执行任意代码。

### 规则字段

| 字段 | 是否必需 | 说明 |
|---|---|---|
| `id` | 建议填写 | 规则唯一名称；省略时自动生成 `custom_序号`。 |
| `enabled` | 否 | 是否启用，默认 `true`。 |
| `priority` | 否 | 匹配检查顺序，数值越大越先检查，默认 `0`；不会阻止其他规则继续命中。 |
| `match_type` | 否 | `literal` 或 `regex`，默认 `literal`。 |
| `words` | 字面规则必需 | 字符串数组，任意一个出现在消息中即命中，不区分英文大小写。 |
| `pattern` | 正则规则必需 | Python 正则表达式，不区分英文大小写。 |
| `exclude_words` | 否 | 任意排除词出现在整条消息中，本规则命中会被排除。 |
| `action` | 否 | 事件动作，默认 `create`。高级值有 `merge`、`intensify`、`ease`、`recall`、`dormant`、`archive`；自定义文本规则通常应使用 `create`，其他动作需要能对应现有事件，否则不会生效。 |
| `target` | 否 | 事件指向对象，默认 `user`。建议使用稳定名称，便于去重。 |
| `valence` | 否 | 情绪方向，范围 `-1.0` 到 `1.0`；负数偏负面，正数偏正面，默认 `0.0`。 |
| `intensity` | 否 | 本次证据强度，范围 `0.0` 到 `1.0`，默认 `0.35`。 |
| `confidence` | 否 | 规则可信度，范围 `0.0` 到 `1.0`，默认 `0.7`。低于 `0.62` 的新证据通常先作为候选，不直接成为有效心事。 |
| `meaning` | 否 | 这段表达对角色内心意味着什么；不填时使用通用说明。 |

规则只产生证据，不会绕过结算器直接修改最终心情。代码块、日志、系统/Bot 文本以及被标记为引用或第三方评价的内容会被排除。

## 与其他插件协作

- **Busy Schedule**：只提供穿着、活动、睡眠和忙碌等事实，不决定最终心情；情绪插件在固定锚点注入连续内心状态。
- **LivingMemory**：可在总结持久化成功后提供情绪观察建议，并向每日回顾提供受限的分段摘要和少量未总结尾部消息。LivingMemory 不可用时，情绪插件仍可独立运行。

## 数据与安全边界

- 每个私聊会话独立保存状态，不在不同用户之间共用心境、心事、日记或身体反应。
- 群聊不处理；AI 回复不作为普通情绪规则和亲密词输入，只做本地待关注事项识别。
- 模型分析失败时回退到本地逻辑，不阻塞正常对话。
- 日记默认只保存并在插件页面展示，不直接注入日常聊天。
