# v0.3.25

提前完成守门（时间守门员）——代码层拦截复核模型把「晚上的约定」在下午标完成。

## 背景

10-04 实锤两类误判（提示词 v0.3.24 已含逐字反例仍拦不住）：

- 「晚上拍白丝视频」（due 23:59）在 13:21 被标完成，证据用的是白天自拍话术；
- 「晚上点丰盛晚饭」（due 23:59）在 15:04 被标完成，证据是「我正点外卖呢」（正在做 ≠ 做完了），且与更早 11:34 的误判用的是同一句话。

12:50 重载后跑的已是 v0.3.24 提示词，说明这是模型能力边界，提示词路线穷尽。

## 方案

在 `apply_attention_observation` 的 complete 分支加代码级守门（不依赖模型自觉）：

- 事项 `due_at` 距现在超过守门阈值（默认 3 小时）→ 拒绝该 complete，理由 `premature_completion_before_due`；
- 截止时间已过或临近（≤3 小时）→ 放行，当晚真实完成不受影响；
- 无 `due_at` 或 `due_at` 无法解析 → 不守门（保持既有行为）；
- `source=webui`（WebUI 人工操作）豁免——人是权威；
- 阈值可配：`attention_premature_complete_guard_hours`（默认 3.0，0 = 关闭守门），经 `EmotionStateService(premature_complete_guard_hours=...)` 注入，三条应用路径（observe_attention / apply_memory_summary / reconcile_attention_history）全部生效。

错误方向安全：拒绝的是 complete（跳过），事项留在 open，有 due_at+1 天宽限归档兜底，不会丢事项。
