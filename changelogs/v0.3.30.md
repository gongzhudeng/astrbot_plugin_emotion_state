# v0.3.30

吃完了还在问「外卖怎么还没点」——守门员看错表，只认「说好的那个点」，不再拿「当天结束」当借口。

## 现象

中午 11:42 说好点麻辣香锅，12:24 外卖已经到门口，人吃完了。

可这条待关注事项一直挂到 **22:02** 才关，中间还被注进提示词，反过来追问「外卖怎么还没给你点」。

## 根因

`core/attention.py` 的 `_premature_complete_rejection` 只看 `due_at` 还剩多少时间：

```python
remaining = due - utc_now()
if remaining > timedelta(hours=guard):   # guard 默认 3.0
    return "premature_completion_before_due"
```

它的本意是防「说好晚上拍，下午拿日常视频糊过去」。但 `due_at` 经常被填成**当天 23:59**（只是「今天有效」的兜底），于是任何在上午/中午完成的事，都被判成「离 23:59 还有十几个小时，不许关」，只能等到 **21:00（23:59 − 3h）之后**才放行。

账本里看得出来：161 条有 due 的已完成事项中，40 条是 due 过了才关、46 条卡在 due 前 1–3 小时；关闭时刻在 21/22/23 点分别 18/16/10 条，**27% 落在 21:00 之后**。

## 改动

1. **`_premature_complete_rejection` 增加时段判据**（`core/attention.py`）

   新增 `_EXPLICIT_PERIOD_CUES`（下午 / 傍晚 / 晚上 / 今晚 / 夜里 / 睡前 / 凌晨 / 明晚 / 明早 / 明天 / 后天 / 大后天 / 周X / 下周 / 下个月）与 `_names_pending_period()`：
   `time_hint` 或 `content` 里**没有**点明时段的事项，即使 `due_at` 还远也放行；
   点明了「晚上 / 明天 / 下午」的，照旧拦。

   故意不含「中午」：外卖类事项常写「今天中午点」，那是当天的事，不该拦到晚上。

2. **原意保留**

   「说好晚上拍视频、下午拿日常视频糊过去」这类误判仍然被拦住——只要那条事项的话里带着「晚上 / 下午 / 明天」，判据和 v0.3.25 完全一致。

3. **即时请求不再建项**（`main.py` 第三任务 + `livingmemory/private_chat_prompt.txt` 两处副本）

   「现在发一段语音 / 拍一段视频 / 再说一句 / 换个说法（再来一句完整的士兵台词）」这类这一轮就能给出结果的请求，直接做，不建项；只有需要跨轮或跨时间的（明天 / 晚上 / 下次 / 等我到家）才建。

   原句「拿不准时倾向于建项」保留不动——它解决的是「死活不建项」，这次只是给「即时请求」划出边界。

   起因：10-24 15:12 那条「用韩语说几句完整的士兵台词、要包含葱橙」，due 为空、time_hint 为空，从建项到被手动删除挂了 10 小时，本身就是一次不该发生的记账。

## 效果

用 459 条真实账本回放：旧规则会拦 30 条，新规则只拦 23 条，**放行 7 条被误伤的「今天」类事项**（如「今天不出门宅在家」「今天拍白丝腿的视频」）。

仍被拦的 23 条全部带明确时段词（明天 / 下午 / 晚上 / 睡前 / 下班后），无误伤。

## 测试

新增 4 例（`tests/test_core.py`）：

- `test_complete_allowed_for_same_day_item_with_end_of_day_due`（麻辣香锅回归）
- `test_complete_allowed_for_immediate_item_even_with_far_due`（待会 / 现在）
- `test_complete_still_blocked_for_tonight_promise`（晚上仍拦）
- `test_complete_still_blocked_when_only_content_names_the_period`（time_hint 缺失时看 content）

`test_core.py` **66 passed**；`attention_premature_complete_guard_hours` 填 0 仍可整体关闭。
