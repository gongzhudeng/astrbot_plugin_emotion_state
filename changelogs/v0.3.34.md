# v0.3.34

她有生理期了；空清单也不再声明「没有」。

## 一、生理期（按角色存一个开始日，其余现算）

新增 `core/cycle.py`（纯函数，110 行）：

- `phase_of(today, settings)` → (阶段, 第几天)：经期 / 经后 / 排卵期 / 经前；
- `body_line()` → 对话注入用的一句体感，非经期返回空串；
- `schedule_hint()` → 给忙碌管理的日程生成用，档位由对方决定；
- 未配置开始日、开始日在未来、日期解析失败，一律返回 `None`，整套静默。

注入位置在**身体反应档位之前**（先说身体怎么样，再说因此怎么反应）：

```
当前心境：平静
经期第2天，小腹坠着，腰有点酸，人没什么劲
当前身体反应档位：平静。身体平静，没有明显性反应。……
```

**刻意不做的**：

- 不进 `ledger.events`（它不是一件事）、不进 `attention_items`（不是待办）；
- 不做「今天说过没」的标记——那要检测她说了什么，会说错；只按日期现算；
- 不做情绪结算的系数偏移：先在表达层跑一段时间，看是不是真需要动数值。

数据文件 `data/plugin_data/astrbot_plugin_emotion_state/cycle.json`，**按角色分键**（生理期属于角色，不属于某个聊天对象，否则同一天对两个人会是两个第几天）。原子写，读失败一律当没配置。

指令：`/生理期`（看状态）｜`/生理期 开始 2026-11-03`（设置）。仅私聊生效。开关与周期长度在配置页。

对外新增回调 `_emotion_state_cycle_context(umo, target_date, level)`，只给忙碌管理用，不进 `_live_context`（那是低敏感公共接口，生理期不该泄漏给所有读它的插件）。

## 二、空清单不再注入占位句

`build_snapshot` 里这两句删了：

> 当前没有足够确定、需要特别带入的具体事情。
>
> 当前没有仍需留意或接续的事项。

判据：**清单类段落空了就不出现，状态类段落必须有值**。清单清空不是信息，说「没有待办」反而在提醒模型「待办」这个类别存在，它会去填补。

`build_live_schedule_context`（给日程修正的低敏接口）本来就没有占位句，本次不动。
