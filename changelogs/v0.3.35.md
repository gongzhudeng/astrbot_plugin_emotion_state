# v0.3.35

待关注事项不再「建了就一直说」：该出现的时候出现，不该出现的时候闭嘴。

## 背景

「星期天提醒我给电动车充电」建完，从那一刻起每轮都在上下文里。周五晚上她就开始念叨周日的事，到周日反而说麻了。

根因在 `select_attention_items`：只要 `open` + 明说 + 置信度够，就一直注入，**没有时间窗口**。

## 四条通道

`should_inject` 决定一条此刻该不该出现，顺序即优先级：

| # | 通道 | 行为 |
|---|---|---|
| 1 | `care`（他此刻不舒服） | 一直注入——它不是「将来的事」 |
| 2 | 已逾期未完成 | 一直注入——这时候才最该催 |
| 3 | 他主动提起了 | 立即注入——不然就是失忆 |
| 4 | 有明确时间 | 只在临近窗口内注入 |
| 5 | 没有明确时间 | 保持现状（一直注入） |

第 2 条会「吃掉」第 4 条：逾期之后不再受窗口约束。

### 窗口怎么算

| 类型 | 提前量 |
|---|---|
| `commitment`（约定） | 到期前 2 小时 |
| `plan`（计划） | 到期前 4 小时 |
| `remember` / `follow_up` | 4 小时 |
| `care` | 不适用 |

**只有日期没有钟点**时按「当天 0 点」算——「星期天」是整天的事，不是周日 22 点才想起来的。

这里有个坑：建项时没给钟点，`due_at` 会兜底成**当天 23:59**。按约定提前 2 小时算，要等到 21:59 才出现，「今晚」这种事等于整晚都不提。所以 `00:00` 和 `23:59` 都按「整天」处理。

## 「他提起了」怎么判断

`extract_mention_keywords` 先切再取：把停用词、人称、单字动词当分隔符，剩下连着的是名词块。

```
"星期天提醒我给电动车充电" → ["电动车充电"]
"Mando说要下影之刃零的盗版" → ["影之刃零", "盗版"]
"三天后提醒我还书"          → ["还书"]   （「三天后」被时间正则去掉）
```

`_mention_matches` 做**双向**匹配：整块出现在话里，或话里 2 字以上的片段落在块里。后者是为了让「电动车充电」被「我充电了」命中——只做单向，长块几乎永远匹配不上。

实测：

```
"我明天去给电动车充电" → 命中
"我充电了"             → 命中
"在吗"                 → 不命中
"车来了"               → 不命中
```

## 顺带修的一个 bug

`on_llm_request` 的 `target == "system"` 分支**没传 `cycle_line`**——如果注入位置配成「系统提示词」，生理期那一句会丢。已补。

## 已知限制

- **只匹配当前这句**，不回溯历史。多轮回溯要靠 livingmemory 的语义检索，这轮没接（成本与收益不划算）；说「对了」下一句才说「充电」的情况会漏掉第一条。
- **他泛问「我最近有什么事」不会触发**。窗口外的事项不注入，模型会说「没有」。要解决得给一个「列出全部」的查询接口，这轮没做。
- **中文不做分词**，词块可能是「电动车充电」这种长块，靠双向匹配兜；极少数词（「还书」这类被单字动词切坏的）提取不到，只能等窗口。
