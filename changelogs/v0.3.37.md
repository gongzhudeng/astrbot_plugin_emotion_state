# v0.3.37

「后天星期天」被模型算成了周一。日期不再问模型，问日历。

## 现象

2026-11-06（周五）20:29，复核模型输出：

```json
{
  "content": "星期天提醒Mando给电动车充电",
  "time_hint": "星期天",
  "due_at": "2026-11-09T09:00:00+08:00"   ← 周一
}
```

用户说的是「后天星期天」= 11-08（周日）。

## 根因不是「模型笨」

复核 prompt 里明写了：

```
当前日期时间：2026-11-06 20:18（周五）。
```

它照样错一天。原因很具体：**模型没有日历**。日期推演要在 token 之间做进位（周五 + 2 = 周日），它擅长的是模式续写，不是算术；「周五」「后天」「星期天」三个词同时出现时，它把「周五」也算进了一天。

而本地 `resolve_due_at("星期天")` 是纯算术：

```python
offset = (target - anchor.weekday()) % 7   # (6 - 4) % 7 = 2
```

**这个一直是对的，只是从来没被用来校验模型给的值**——原来的写法是 `due_at=observation.due_at or resolve_due_at(...)`，模型只要给了值就无条件采用。

## 改法：日期信代码，钟点信模型

新增 `reconcile_due_at(time_hint, model_due)`：

| 情况 | 处理 |
|---|---|
| `time_hint` 解析不出 | 保留模型给的值（可能是「11月20日上午十点」这种绝对表述） |
| 两者日期一致 | 保留模型的（它可能给了更精确的钟点，如 15:30） |
| 日期不一致 | **用日历算的日期**，保留模型给的时分 |

这样修的是分工问题，不是「错了就纠正」：一开始就不该让模型决定日期。

## 为什么不做成「校验后报警」

报警要人看，而这是在无人值守的复核链路里。用户永远不会知道那条 due 错了，只会在周日发现她没提醒——正是 11-06 发生的事。所以必须就地纠正，不留待人工。
