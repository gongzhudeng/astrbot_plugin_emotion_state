# v0.3.40

表达建议学会「有话直说」：被晾、被敷衍、被忽略，都明着讲。

## 起因

他打游戏三小时没回，中间她找过两次。回来聊的时候，表达建议还是说「按平时明快的状态聊就行」，`avoid` 里甚至写着「不要硬扯难过」。

用户要的不是阴阳怪气或冷处理，是**把缘由说出来**。

## 一、材料里补了「沉默时长」

原来 `payload` 里没有这个数字，表达建议就算想计较也无据可依——它只能看到心情，看不出「被晾了」。

```json
"silent_minutes": 185
```

从 `ledger.last_user_message_ts` 算（这个字段一直有，只是没传下去）。

## 二、五条情境，全部要求明说

写进提示词：

> **有话直接说，别憋着让人猜**：可以带气、可以损他，但**不冷处理、不阴阳怪气、不让他自己反省**；说的时候落到具体那件事上，不上升到人品，不说教。

| 情境 | 给的方向 |
|---|---|
| 很久没回（`silent_minutes` 大） | 直接说被晾着不舒服，点出多久没动静，别翻旧账 |
| 他敷衍（连着「嗯/哦/好」） | 直接点出来「你这是在敷衍我」，不高兴放在明面上 |
| 提到别的女生 / 看美女 | 直接说不高兴、问清楚，不审问不查岗 |
| 答应的事没做 | 翻出来说，只翻这一件，不叠旧账 |
| 熬夜 / 不吃饭 / 硬撑 | 心疼包在念叨里，说具体「几点了还不睡」 |

三条防滥用的边界：**一次只挑最明显的那个**、材料里没有信号就别硬找、数字不要照抄（说「你这一下午都没影」而不是「185 分钟」）。

## 三、静置结算：算法是好的，入口进不去

`proactive_applied_stage` 一直是 0，`proactive_evidence_progress` 是空列表——这套静置结算从没跑过。

但我用真实数据直接调 `settle_proactive_evidence`：

```
证据 16 条 → 事件 +3，进度 +16
```

**算法本身没问题**。所以卡在插件层：`_settle_proactive_state` 在 `available=False` 时静默 return，看不出是「没装 Spark」还是「取不到它的状态」。

本次只加一条 debug：

```
[EmotionState] proactive snapshot unavailable for <user_key>
```

重载后如果这条刷出来，就确认是取不到 Spark 状态；没刷出来则要往 `mutate_if_changed` 那边查。**没修**，先定位。

`test_reminder_close_guard` 和 `test_update_due_is_also_reconciled` 里写死了 `2026-11-09`，那天一过就全红（因为建项会判「截止时间已过」）。改成相对现在三天后 / 只断言落在周日。
