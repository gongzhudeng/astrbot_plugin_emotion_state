# v0.3.47

改过时间的提醒，永远不再响。

## 现象

11-22 那条充电事项定在 15:00，到点没有任何提醒。

## 真相：提醒过两次，只是用旧时间

```
12:00:10  执行 + 送达    （due 原来是 12:00）
12:30:16  执行 + 送达    （重复间隔 30 分钟）
```

13:45 把 due 手工改到 15:00，**但 `notify_count` 还是 2**。

15:00 判定时：

```
notify_count(2) >= max_count(2) → 跳过
```

## 根因在代码，不只是手工失误

`update` 分支和 `merge_attention_duplicate` 改 due 时都没有清计数。
只要一条事项被改过时间、且之前提满过次数，它就再也不会提醒。

## 改法

时间真的变了（新值非空且不等于旧值）就重置：

```python
current.notified_at = ""
current.notify_count = 0
```

两条路径都加了：`update` 分支、合并覆盖时间分支。

## 测试

`test_retime_resets_notify_count`：提满 2 次 → 改时间 → 计数归零。

**272 绿**。

## 数据

账本里那条仍是 `notify_count=2`、`due=15:00`。是否重置由用户决定
（重置后下一次 tick 会立刻补一次提醒）。
